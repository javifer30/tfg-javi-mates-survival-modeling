# MIMIC-IV Extracted Data Documentation

This document explains the structure and purpose of the raw extracted datasets found in `data/processed/mimic_extraction/`. These files are generated by the `mimic_direct_extraction.py` script, which extracts specific cohorts and features directly from the raw MIMIC-IV database files (`.csv.gz`).

## 1. Data Files Overview

The extraction process produces four primary CSV files. These serve as the input for the subsequent preprocessing and machine learning pipeline.

### A. `labels.csv` (Patient Cohort & Targets)
This file defines the study cohort and contains the target variables for prediction.

*   **Row Entity:** One row per patient stay (Unique ICU stay).
*   **Ordering:** Sorted by `patientunitstayid`.
*   **Columns:**
    *   `uniquepid`: The unique patient identifier (Subject ID from MIMIC).
    *   `patienthealthsystemstayid`: Hospital admission ID.
    *   `patientunitstayid`: **Key Identifier.** The unique ID for the ICU stay. Used to link all other tables.
    *   `actualhospitalmortality`: **Target 1.** Binary outcome (0 = Survived, 1 = Died in hospital).
    *   `actualiculos`: **Target 2.** Length of Stay in ICU (in days).
    *   `intime`: Timestamp of ICU admission.
    *   `outtime`: Timestamp of ICU discharge.
    *   `age`: Patient age at admission.
    *   `gender`: Patient gender.
    *   `ethnicity`: Patient ethnic group.
    *   `first_careunit`: The type of ICU (e.g., MICU, SICU) they were first admitted to.
    *   `admission_location`: Where they came from (e.g., Emergency Room).
    *   `insurance`: Insurance type.

### B. `flat_features.csv` (Static Clinical Features)
This file contains clinical data that is treated as "static" or "baseline" for the model. These values are extracted from the time of admission (specifically -24 hours to +5 hours relative to admission).

*   **Row Entity:** One row per patient stay (matches `labels.csv`).
*   **Ordering:** Sorted by `patientunitstayid`.
*   **Columns:**
    *   `patientunitstayid`: **Key Identifier.**
    *   `gender`: (Duplicate from labels, often encoded later).
    *   `age`: (Duplicate from labels).
    *   `ethnicity`: (Duplicate from labels).
    *   `first_careunit`: (Duplicate from labels).
    *   `admission_location`: (Duplicate from labels).
    *   `insurance`: (Duplicate from labels).
    *   `height`: Patient height (cm).
    *   `weight`: Patient weight (kg).
    *   `hour`: The hour of day of admission (0-23).
    *   `eyes`: Glasgow Coma Scale (GCS) Eye Opening score (baseline).
    *   `motor`: GCS Motor Response score (baseline).
    *   `verbal`: GCS Verbal Response score (baseline).

### C. `timeserieslab.csv` (Dynamic Lab Tests)
This file contains time-varying laboratory test results extracted from the `labevents` table.

*   **Row Entity:** One measurement event. A patient has multiple rows.
*   **Ordering:** Sorted by `patientunitstayid`, then `labresultoffset`.
*   **Columns:**
    *   `patientunitstayid`: **Key Identifier.**
    *   `labresultoffset`: The time of the measurement, expressed as **minutes from ICU admission**.
        *   Negative values indicate tests done shortly before entering the ICU (up to 24h prior).
        *   Positive values indicate tests done during the stay.
    *   `labname`: The name of the test (e.g., "glucose", "potassium").
    *   `labresult`: The numerical value of the test result.

### D. `timeseries.csv` (Dynamic Chart Events)
This file contains time-varying vital signs and other charted observations extracted from the `chartevents` table.

*   **Row Entity:** One measurement event.
*   **Ordering:** Sorted by `patientunitstayid`, then `chartoffset`.
*   **Columns:**
    *   `patientunitstayid`: **Key Identifier.**
    *   `chartoffset`: The time of the measurement, expressed as **minutes from ICU admission**.
    *   `chartvaluelabel`: The name of the measurement (e.g., "Heart Rate", "O2 Saturation", "BP").
    *   `chartvalue`: The numerical value of the measurement.

## 2. From Extraction to Preprocessing

The files above are "raw" in the sense that they still contain irregular time stamps and unnormalized values. The pipeline transforms them into the final tensors used for training models (like DeepSurv or LSTMs).

### The Logic of Transformation

1.  **Normalization & Cleaning (Flat Data):**
    *   The `flat_features.csv` and `labels.csv` are merged.
    *   Categorical variables (ethnicity, unit) are **One-Hot Encoded**.
    *   Continuous variables (Age, Height, Weight) are **Z-score Normalized** (subtracted mean, divided by std dev) or Scaled to a specific range.
    *   Missing values are imputed (e.g., with mean or 0) and sometimes flagged with a binary "is_missing" column.
    *   **Result:** `preprocessed_flat.csv` and `preprocessed_labels.csv`.

2.  **Resampling & Formatting (Time Series):**
    *   The `timeseries.csv` and `timeserieslab.csv` are merged into a single stream of events.
    *   **Pivoting:** The "long" format (Name, Value) is pivoted to "wide" format, where each column is a feature (Heart Rate, Glucose, etc.).
    *   **Resampling:** The irregular time offsets (e.g., min 5, min 12, min 45) are resampled into fixed **hourly bins** (Hour 0, Hour 1, Hour 2...).
        *   If multiple measurements occur in an hour, they are averaged.
        *   If no measurement occurs, the value is forward-filled (carry forward the last known value) or imputed.
    *   **Normalization:** All time-series features are scaled (usually to -1 to 1 or 0 to 1 range) using global statistics calculated from the training set.
    *   **Result:** `preprocessed_timeseries.csv` (or the final split files).

### The Final "Processed" Table Idea

The ultimate goal is to create a 3D Tensor for the model:
`[Batch Size, Time Steps, Features]`

*   **Time Steps:** Each row in the final processed time-series file represents **one hour** of a patient's stay.
*   **Features:** The columns represent the state of the patient at that hour (HR, BP, Lab values).
*   **Masking:** Since patients stay for different lengths of time, shorter stays are "padded" with zeros, and a **Mask** is created to tell the model which time steps are real data and which are padding.

The final dataset you feed into the model consists of:
1.  **X (Static):** The vector from `preprocessed_flat.csv`.
2.  **X (Dynamic):** The sequence of vectors from the processed time series.
3.  **Y (Target):** The mortality/LOS values from `preprocessed_labels.csv`.
